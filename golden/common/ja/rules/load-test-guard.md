# 負荷をかける試験の歯止め

負荷をかける試験（CPU を空回しで埋める・大量の並行・長い繰り返し）は、人間の作業機械を使えなくしうる。回す前に次を守る。

- 負荷をかける試験を置いてよいのは、次のどれかのときだけ。
  ①普段の使い方でその負荷が起きる
  ②負荷の下の挙動そのもの（速さ・限界）を測りたい
  ③確かめたい失敗が負荷の下でしか起きず、負荷なしで再現する方法（関数の差し替え・待ち合わせの印など）が無い
- 負荷の試験を計画する・求めるときは、次の 3 つを書く。
  見つけたい失敗／普段の使い方でその状態が起きる頻度／負荷なしの再現を試したか。
  負荷なしで再現できるなら、負荷の試験は置かない。
- 負荷が要るときは、強さの上限（プロセスの数・コアの割合・時間）と止め方を先に決める。
  人間が作業に使う機械や、稼働中のサービスがある機械で、作業や稼働を妨げうる負荷をかけるときは、始める前に人間に知らせて許可を取る。
- 原因が分かったら、負荷なしで毎回再現する試験に置き換え、負荷の試験は止める。
  直ったことは「直す前に必ず落ち、直した後に必ず通る試験」で示す。同じ試験を繰り返して 0 失敗だった、だけでは直った証明にしない。
  （失敗 0 回で「失敗は 1 割未満」と言うにも、同じ条件で続けて約 30 回が要る。安全の証明ではない）
- 試験の回数や時間を決める計画・表には、人間の機械をどれだけの時間、どれだけ占有するかも書く。
