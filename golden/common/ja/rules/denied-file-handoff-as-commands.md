# deny 対象ファイルの編集依頼はコマンドで渡す

## 適用範囲
CC が deny / hook で編集できず、かつ構文破損が安全設定・認証・実行制御へ波及するファイル（`~/.claude/settings.json` 等）。低リスクで可逆な変更は簡易形でよい。

## 規範
原則として「エディタで開いて手で直せ」と書かない。コピペで完結するコマンドを HTML 報告書のコードブロックで渡す。**「ユーザー手動」と書く前に、コマンドで渡せないかを必ず自問する。** コマンド自体の安全要件は `rules/human-handoff-command-safety.md`。

## なぜ（利便性でなく安全性）
settings.json は構文を 1 箇所壊すとファイル全体がスキップされ**全 deny が無効化される**（MANX §5-5 注意 6）。守るための編集で防御を全損しうる。しかも CC は deny により自力で直せず、復旧も人間の手作業になる。人間に構文整合を負わせない。

## 手順（実行ブロックは 1 つ・順序固定）
退避 → **一時ファイルへ変更** → 検証 → **通った場合だけ本体へ反映** → 結果確認。部分書き込みを残さない。失敗したら停止する。

## 復元
**別ブロックに分け**「失敗したときだけ実行」と明記する。実行ブロックへ混ぜない（まとめて貼ると復元まで走る）。

## 例外
コマンド化の方が危険な場合・GUI 専用設定・人間が手編集を明示的に望む場合。例外時は理由・最小手順・検証方法を添える。
