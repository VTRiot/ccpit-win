# imaging-proxy-verbatim-read — 画像化プロキシ配下での逐語読み取り

## 1. 適用状況

### 1-1. 環境条件

- 会話の入力側に画像化プロキシが入っている（system prompt やツール結果が画像として届く。元テキストの代わりに識別子の列挙だけがテキストで残る）

本 skill は**モデル・版に依らず**適用する。画像からの逐語精度はモデルや版で変わる（同族モデルでも版で落ちる実例がある）が、「画像から転写した値を根拠に使わない」という原則はどのモデルでも同じであり、精度が高いと見込まれるモデルでも画像経由の値を採用しない。

### 1-2. 適用する読取（逐語値）

**1 文字違うと意味が変わる、または対象に辿り着けなくなる値**。これらは画像化された出力から読まず、§3 の手順でテキストとして取る:

- ハッシュ（sha256 等）・PID・ポート番号・行番号・バイト数や行数など、検証や照合に使う数値
- ファイルパス・ファイル名・ディレクトリ名・URL・版番号・識別子（request_id・UUID・コミットハッシュ）
- コマンド引数にそのまま渡す値、引用としてそのまま書き写す値、人間や別ツールの照合に供する値

判定は「その値を**そのまま**引用・引数・照合に使うか」で行う。使うなら逐語値として本 skill を適用し、使わないなら 1-3 に従う。

### 1-3. 適用しない読取（要旨で足りるもの）

文脈から復元でき、多少の識字の誤りが結果に影響しない読取には本 skill を**使わない**。画像化されたまま要旨として読み、分割再取得もしない（画像化によるトークン削減を殺さないため。逐語値の分割取得はここで浮いたトークンの一部を使う関係にある）:

- 説明文・設計文書の趣旨、レビューコメントの意図
- ログやエラーメッセージの傾向（何が失敗したか）
- コードの構造や処理の流れの把握（どの関数がどこを呼ぶか）
- 一覧の「おおよその件数」「含まれているか否か」

ただし、要旨として読んだ中の値を後で引用・引数・照合に使うことになった時点で 1-2 に移り、**その値だけ**をテキストで再取得する。要旨として読んだ値をそのまま流用しない。要旨把握の品質そのものは本 skill では扱わない。

本 skill が防ぐのは**画像化由来の誤読**だけである。読んだ値が今も有効か（PID の生存・ポートの占有・ファイルの更新）は別問題で、§4 の末尾に扱いを書く。

## 2. 画像化の判定

ツール結果を受けたら、次の 2 段で判定する。

**確定** — 次のいずれかがあれば「画像化された」と確定する:

- 結果本文が画像として届いている
- 元テキストの代わりに、識別子の列挙（「Exact identifiers from the rendered context」等のレンダリング標識）だけがテキストで残っている

**疑い** — 確定条件は無いが、期待した行数・項目数のテキストが無く、要約的な短文しか無い。これは画像化のほかに、コマンド失敗・切り詰め・ツール側の要約でも起きる。切り分けは次の**プローブ**で行う:

- プローブに使えるのは、**期待する結果が直前の確定済み結果から既に分かっている照会**だけである。例: `ls -la -- '<file>'` で実在とバイト数を確認済みなら `wc -c -- '<file>'` は同じバイト数を 1 行で返すはず。`grep -c '^## ' -- '<file>'` の結果を見出し数として使うなら、その前に `grep -n '^## ' -- '<file>'` をテキストで受け取れていること
- プローブの形は `<cmd>; echo exit=$?` の 1 呼び出し。**コマンド本体の stdout はデータ行ちょうど 1 行、stderr は空**であること。末尾の `exit=<n>` は制御行で、期待値との比較は**データ行だけ**で行う。データ行が 0 行（`exit=` 行のみ）なら空出力、終了コードが 0 でない・stderr がある場合はコマンド側の失敗であり、いずれも画像化の判定材料にしない
- プローブのデータ行が既知の期待と**一致**すれば、元の出力は失敗ではないので画像化を疑い、§3 の手順で絞って再取得する。**一致しない**か、期待を持てるプローブが作れないなら、原因（画像化・失敗・要約）を特定しようとせず、元の出力の値を**未検証**として扱う（§3-1 の終了条件）

画像化が確定した結果から読み取った数値・ハッシュ・パスは**採用しない**。要旨の把握には使ってよいが、配置検証・引用・コマンド引数には使わない。

## 3. 限定して取る手順

画像化はサイズ閾値で決まり、閾値の具体値は環境設定で変わるため本 skill には書かない。判定は §2 の兆候で行い、取得は次の順で出力を小さくする。

### 3-1. 共通原則

1. **対象を先に限定する**: 単一ファイル・単一ポート・単一 PID・単一ディレクトリ直下、のように「何を読むか」を引数で絞ってから実行する
2. **1 回のツール呼び出しに複数の取得を束ねない**: `ls` と `wc` と `sha256sum` を `&&` や `;` で繋ぐと合計サイズで画像化される。逐語値が要る取得は 1 呼び出し 1 コマンド（§2 の `; echo exit=$?` のような制御行 1 行の付加は除く）
3. **結果ごとに §2 で再判定する**: 「小さいはず」の見込みは保証ではない。見出し数が多い・行が長い・パスが長い等で出力は膨らむ
4. **画像化されたら、画像から転写して埋めない**。次の順でさらに絞って再取得する: **対象指定 → 列選択 → 件数制限 → 個別照会**
5. **終了条件**: 単一値の個別照会（1 行・1 件・1 ファイル）まで絞ってもテキストとして確認できない、結果が空、抽出結果が 1 件に定まらない、または所有者・値を確認できない場合は、その値を**未検証**として報告する。未検証の値は引用・コマンド引数・破壊的操作（プロセス停止・上書き・削除）に使わず、再試行を続けない。原因の特定（画像化か失敗か権限か）は報告に必須ではない

### 3-2. 値の種類別の絞り方（POSIX shell）

**プレースホルダーの埋め方**（表と本文の全例に共通）。コマンドはエージェントが 1 呼び出しごとに手で埋めるので、埋めた結果が**シェルにそのまま渡る安全なリテラル**になる形に限る:

- `<file>` `<dir>` `<語>` は**単引用符**で囲む: `'<file>'`。二重引用符は `$(...)`・バッククォート・`$var` を展開するので使わない（実測: `-a $(x) \`y\` b.txt` というファイルは `'…'` で全コマンドが通り、`"…"` では失敗した）。値の中に `'` があるときは `'\''` で繋ぐ（例: `it's.txt` → `'it'\''s.txt'`。実測で通る）
- **ファイル名の引数の前に `--` を置く**: `wc -c -- '<file>'`。先頭が `-` のパスをオプションとして読まれないため。`ls` `wc` `sed` `head` `grep` `sha256sum` `shasum` で実測済み（Git Bash・WSL）
- `<語>` は固定文字列で、`grep -n -F -- '<語>' '<file>'` のように **`-F`**（正規表現として解釈しない）を付ける。`--` の後の最初の引数がパターン、次がファイル
- `<port>` は**数字だけ**であることを確認してから埋める。`<a>` `<b>` `<k>` `<n>` は正の整数
- `<値のパターン>` だけは正規表現（`grep -o -E` 用）で、意図して書く。これも単引用符で囲む

| 値の種類 | 対象指定 | 列選択 | 件数制限 | 個別照会 |
|---|---|---|---|---|
| ファイル本文の行 | 行範囲 `sed -n '<a>,<b>p' -- '<file>'` | 長い行は下記「長い行」 | 範囲を半分にする | 1 行ずつ `sed -n '<k>p' -- '<file>'` |
| 見出し・行番号 | `grep -n '^## ' -- '<file>'` | — | `head -n <n>` | 見出し語で `grep -n -F -- '<語>' '<file>'` |
| 行数・サイズ | `wc -l -- '<file>'` / `wc -c -- '<file>'` | — | — | — |
| ハッシュ | 下記「ハッシュ」（単一ファイル） | — | — | — |
| ディレクトリ一覧 | `ls -la -- '<dir>/<name>'`（単一エントリ） | `ls -1` で名前だけ | `ls -1 -- '<dir>' \| head -n <n>` | `ls -la` を対象名ごとに |
| ポート → PID | §3-3（OS ごとに出力形式が違う） | | | |

- **ハッシュ**: `sha256sum` は POSIX 標準ではない（GNU coreutils）。先に `command -v sha256sum shasum` で**両方の有無**を確認する（実測: Git Bash は両方、WSL は `sha256sum` のみ。macOS 標準は `shasum`）。`sha256sum -- '<file>'` があればそれ、無ければ `shasum -a 256 -- '<file>'`。**どちらも無ければハッシュは未検証**として報告する（別のハッシュ機構を使う場合は §6 の「別経路」として、何で取ったかを明示する）。どちらも `<hash>  <file>` の 1 行を返す
- **長い行**: 逐語値が行の後方にあるとき、`cut -c1-<n>` では届かない。値の形が分かっているなら、**対象行を先に 1 行に限定した上で** `grep -o -E` で値だけを抽出する: まず件数を確認し（`sed -n '<k>p' -- '<file>' | grep -o -E '<値のパターン>' | wc -l`）、**ちょうど 1 なら**次の呼び出しで `| wc -l` を外して値を取る。0 件または複数件は未検証（`grep -o` は一致した値を全件出すので、複数件は再び画像化され得るうえ採用する値が決まらない）。パターンが書けず範囲で切るなら、**行が ASCII だけ**の場合に限り `cut -c<a>-<b>` を範囲ごとに別呼び出しで使う。Git Bash・WSL の coreutils の `cut -c` は**バイト単位**で切る（実測: `あいう` を `cut -c1-2` すると 1 文字目の途中 2 バイトが出る）ため、非 ASCII 行を `cut` で分割しない。非 ASCII 行で値をパターン抽出できなければ未検証とする
- ディレクトリ全体のような「全部」を 1 回で取る必要がある場合は、まず件数（`ls -1 -- '<dir>' | wc -l`）を取り、件数に応じて範囲を分けて取る

### 3-3. ポート → PID の絞り方（OS 別）

ポート占有の出力は OS ごとに列位置・状態語が違うため、汎用の正規表現を書かない。共通原則は「**ローカルアドレス列**の当該ポート・**Listen 状態**・プロトコルの 3 条件で絞る」「PID が複数残ったら任意の 1 件を採らず、PID ごとに個別照会する」「PID 列が空なら所有者を確認できないため未検証」。`<port>` は数字だけであることを確認してから埋める（§3-2）。

- **Windows（Git Bash 上の Windows `netstat`）**: 出力は「プロトコル / ローカル / 外部 / 状態 / PID」の 5 列。IP の表記を正規表現で限定せず**列で判定**する（IPv4 `127.0.0.1:<port>` と IPv6 `[::]:<port>` の両方に当たる）:
  `netstat -ano | awk '$1=="TCP" && $2 ~ /:<port>$/ && $4=="LISTENING" {print $2, $5}'`
  `$2 ~ /:<port>$/` はローカル列の末尾ポートだけに当たり、外部アドレス側の同じポートや接続中の行を除く。`:<port>` を行全体に `grep` すると行数と PID が増える（実測: 未固定 7 行 → 固定 1 行）
- **Linux**: `ss -ltnp 'sport = :<port>'`（Listen・TCP・数値表示・当該ポートに限定）。PID は `pid=<n>` として Process 列に出る。**Process 列が空**の場合（実測: 他ユーザー所有の listener で空になる。競合終了など他の原因もあり得る）は理由を断定せず、所有者を確認できないため未検証とする。`lsof -nP -iTCP:<port> -sTCP:LISTEN -t` も同じく確認できない場合は空を返す
- **PowerShell**: `Get-NetTCPConnection -LocalPort <port> -State Listen | Select-Object -ExpandProperty OwningProcess`

## 4. 逐語値の扱い

- 配置検証・報告・コマンド引数に使う値は、**画像化されていないと判定した当該コマンド結果**から引く。別の呼び出しの記憶や、画像化された結果の識別子列挙から補わない
- 画像化された結果に含まれる識別子の列挙は、**その値が本文のどこかに存在する**手がかりにはなるが、どの行・どの文脈の値かは示さない。文脈が要る場合はテキストで再取得する
- 人間の照合に供する値（sha256 等）は、**取得コマンドの出力をそのまま引き写す**（桁の省略・大文字小文字の変更・空白の除去をしない）。比較側と表記が違う場合は、引き写した生の値とは**別に**「比較用に正規化した値」を作り、どの正規化を施したかを添える（例: PowerShell の `Get-FileHash` は大文字で返すので、比較時に小文字化した旨を書く）
- **行数の定義**: POSIX の `wc -l` は LF の個数、PowerShell の `Get-Content` の `.Count` は論理行数で、末尾に LF が無いファイルでは 1 差が出る（実測）。環境をまたいで同一ファイルを照合するときは行数でなく**バイト数（`wc -c` / `.Length`）とハッシュ**で比較する。行数を使うなら「LF 数」か「論理行数」のどちらかを明示する
- **鮮度・同一性は本 skill の範囲外**。PID・ポート・更新中のファイルは取得後に変わり得るので、その値でプロセスを止める・ファイルを上書きする直前には再取得する

## 5. 例

配置検証（実在・行数・ハッシュ・先頭行・見出し）を 1 回の呼び出しで束ねると、対象が長い MD なら画像化されることがある。次の各ブロックは**それぞれ別のツール呼び出し**として実行する。**ブロック群をまとめて 1 回で実行しない。** `<file>` は §3-2 の規則どおり単引用符で囲み、`--` の後に置く。

```bash
ls -la -- '<file>'            # 実在・サイズ（単一ファイル）
```

```bash
wc -c -- '<file>'             # バイト数（環境をまたぐ照合はこれとハッシュ）
```

```bash
command -v sha256sum shasum   # ハッシュコマンドの有無（両方無ければハッシュは未検証）
```

```bash
sha256sum -- '<file>'         # 上で選んだ方を 1 回だけ実行（無ければ shasum -a 256 -- '<file>'）。生の出力を引き写す
```

```bash
head -n 1 -- '<file>'         # 先頭行（末尾行が要るなら tail -n 1 -- '<file>' を別呼び出し）
```

```bash
grep -n '^## ' -- '<file>'    # 見出しと行番号
```

## 6. 関連 skill と分担

- `large-doc-section-probe`: 巨大な**文書**から該当節を特定して読む。両者が同時に発火する（巨大文書から逐語値を取る）場合は、**節の特定は同 skill、各出力の画像化判定と再取得は本 skill**が担う。本 skill を別 skill として置く理由は、対象が文書に限らずポート・ハッシュ・ディレクトリ一覧など任意のツール出力に及ぶこと
- `tool-path-cross-verification`: 値の突き合わせが要るときの手順。**発火条件**は次のいずれか: (a) 別々の呼び出しで得た同一対象の値が食い違った（例: `ls -la` のバイト数と `wc -c` が違う）、(b) 画像化された結果から要旨として読んだ値と、テキストで再取得した値が食い違った、(c) 未検証にはならなかったが、その値を破壊的操作の引数（kill する PID、上書きするパス）に使う。常時の照合は要らない
  - **導入済みなら**同 skill に従う
  - **未導入なら**、独立した別経路で同じ値を 1 つ追加取得し、一致しない限り採用しない。「独立した経路」の最低条件は、**同じ出力の再整形ではなく、別の取得機構で対象を直接照会すること**（例: `sha256sum` に対して `Get-FileHash`、`netstat` に対して `Get-NetTCPConnection`、`wc -c` に対して `ls -la` のサイズ列）。一致しなければ §3-1 の終了条件に従い未検証として報告する

## 7. 実行環境の前提

本文のコマンド例は **POSIX shell**（Claude Code の Bash ツール、Git Bash、WSL 等）を前提にする。`sha256sum` のように POSIX 標準でないものは §3-2 に代替を書いた。`netstat`・`ss` など OS 固有の出力形式に依存するものは §3-3 で OS ごとに分けた。プレースホルダーの埋め方（単引用符・`--`・`-F`・数字確認）は §3-2 の規則に従う。PowerShell では `-LiteralPath '<file>'` も**単引用符**で囲む（PowerShell の単引用符は変数・部分式を展開しない。値の中の `'` は `''` と 2 つ重ねる）。PowerShell のみの環境では次の等価で同じ原則（対象を限定し、1 呼び出し 1 取得、生の値を引き写す）を守る:

| 目的 | POSIX | PowerShell |
|---|---|---|
| 行数（定義は §4） | `wc -l -- '<file>'`（LF 数） | `(Get-Content -LiteralPath '<file>' -Encoding UTF8).Count`（論理行数。`Measure-Object -Line` は空行を数えないので使わない） |
| 行範囲 | `sed -n '<a>,<b>p' -- '<file>'` | `Get-Content -LiteralPath '<file>' -Encoding UTF8 \| Select-Object -Skip (<a> - 1) -First <n>`（`<a>` は正の整数。`-Skip <a>-1` と書くと整数に変換できず失敗する） |
| 見出しと行番号 | `grep -n '^## ' -- '<file>'` | `Select-String -LiteralPath '<file>' -Encoding UTF8 -Pattern '^## ' \| Select-Object LineNumber, Line` |
| 固定文字列の検索 | `grep -n -F -- '<語>' '<file>'` | `Select-String -LiteralPath '<file>' -Encoding UTF8 -SimpleMatch -Pattern '<語>' \| Select-Object LineNumber, Line` |
| バイト数 | `wc -c -- '<file>'` | `(Get-Item -LiteralPath '<file>').Length` |
| ハッシュ（生の値） | `sha256sum -- '<file>'` または `shasum -a 256 -- '<file>'`（小文字） | `(Get-FileHash -LiteralPath '<file>' -Algorithm SHA256).Hash`（大文字。比較時の正規化は §4） |
| ポート → PID | §3-3 | `Get-NetTCPConnection -LocalPort <port> -State Listen \| Select-Object -ExpandProperty OwningProcess` |

PowerShell で非 ASCII の本文を逐語確認する場合、`-Encoding UTF8` を付けてもコンソール出力の符号化が UTF-8 でなければ文字が化ける。数値・ハッシュ・PID・行番号の取得には影響しないが、**非 ASCII のファイル名・本文の逐語確認は POSIX shell 側で行う**か、コンソール出力の符号化を UTF-8 に揃えてから行う。
