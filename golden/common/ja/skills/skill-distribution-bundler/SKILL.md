# skill-distribution-bundler — 配布バンドル化ゲート

## 発火条件
- 「この skill / ツールを誰かに渡したい・配布したい・プレゼントしたい・共有したい」。
- 「インポートできる形にまとめて」「バンドル/ZIP にして README を付けて」。
- 自ホストへの搬入（inbound）ではない。本 skill は outbound（自作物を他者へ出す）専用。

## 大原則
- **元の skill / ファイルは無変更**。必ず別フォルダへコピーを作り、編集対象はコピーのみ。
- 配布物に「動くもの第一責務」を適用する。構文 OK / typecheck OK は前提条件。受領者環境で動く形にして初めて完了。
- 不可逆操作（元ファイル上書き・既存配布物の置換）は事前確認。

## ワークフロー

### 1. 受領者プロファイルの確定（最初に必ず）
- 受領者の OS（Win / macOS / Linux）、ランタイム（pwsh / python / node 等）、認証前提（API キー要否・ログイン要否）を確定する。
- 不明なら聞く。OS を取り違えると移植方針ごと変わるため、ここは推測しない。

### 2. コピー土台の作成
- 配布用ステージングディレクトリを作り、対象一式をコピーする。
- ロジックファイル（.ps1/.py/.js 等）は原則無改変コピー。ドキュメント（.md）はサニタイズ対象。

### 3. 私的固有語のサニタイズ（全数 grep）
- 人名・社名・プロジェクトコードネーム・AIセッション名・内部開発語・内部ドキュメント参照（正本パス等）を**全数 grep**で洗い、一般語へ置換する。
- ロジックの**挙動を変えない範囲**で、コメント・実行時メッセージ文字列中の内部語も整える（受領者の画面に出る文字列は特に）。
- 置換後にもう一度 grep して残存ゼロを確認（1件目で満足しない）。

### 4. OS依存箇所のクロスプラットフォーム移植（全数 grep）
- 全数 grep で OS 依存を洗う（例: `$env:USERPROFILE`/`%USERPROFILE%`/`$HOME`、ドライブレター `C:\`、`\` 区切りパス、OS固有コマンド、改行コード）。
- 移植先 OS で壊れる箇所のみ最小修正。可搬な書き方へ（例: home 解決は環境変数が無ければ `$HOME` フォールバック＋OSネイティブのパス結合、パスはスラッシュ統一）。
- 「実ロジックで移植先を壊す箇所」と「単なる説明文」を切り分け、前者を確実に直す。

### 5. 受領者向け README（同梱必須）
- バンドル直下に受領者視点の README を置く。最低限: 何のツールか / 前提（ランタイム・認証・インストール手順）/ インストール先と配置コマンド / スモークテスト（生成や実行をしない疎通確認＋実走確認）/ 主要オプション / お品書き（同梱物一覧と各ファイルの素性）/ 注意（権利・安全）。
- 移植で変えた箇所は README の「お品書き/素性」に明記する（無改変か・どこを直したか）。

### 6. 検証（報告前に必須・推測で完了宣言しない）
- スクリプトは構文パース検証（全ファイル）。可能なら DryRun 等の副作用なし経路で結線確認。
- 実走 end-to-end が当環境で不可能なら、その旨を「未検証」と正直に明示し、受領者の初回確認項目として README に書く。

### 7. ZIP 梱包と中身確認
- ZIP 化は review-bundle-zip 系の梱包を流用してよい。
- **ZIP 内エントリ一覧を必ず確認**: 想定ツリー通りか／`.bak`・検証用スクリプト・一時ファイル等の混入が無いか。
- 配布物パス・同梱物・検証結果・未検証項目を簡潔に報告する。

## チェックリスト（完了ゲート）
- [ ] 元ファイルは無変更（編集はコピーのみ）
- [ ] 私的固有語 残存ゼロ（置換後 grep 済み）
- [ ] OS依存 全数確認・移植済み（受領者OSで動く）
- [ ] 受領者README 同梱（前提/導入/スモークテスト/お品書き/注意）
- [ ] 全スクリプト構文OK＋可能なら副作用なし結線確認
- [ ] ZIP中身確認（想定ツリー／混入なし）
- [ ] 未検証項目があれば正直に明示

## 注意
- 著作権・ライセンス・権利表記を配布前に確認。第三者素材の同梱可否を点検する。
- 私的設定（個人パス・トークン・ローカル前提）を配布物に残さない。
