# コード引用の実物照合（`cite=` / `include=` / `rev=`）

> この章を開く作業: 報告書にファイルのコード片を引用する時

## コード引用の実物照合（任意・`cite=` / `include=` / `rev=`）

報告書にコード片を引用するとき、手で写すと写し間違い・行番号のずれが起きる。実際に、実物に無いコード片の引用と、行番号が 4 か所ずれたままの引用が、報告書の中の自己監査表で「完全一致」と書かれて通った。手で書く表では止まらないので、フェンスの info 文字列に属性を書くと、`--verify` が実物のファイルと機械で照合する。**属性を書かないフェンス・文書は一切影響を受けない**（HTML も `--verify` の出力も従来と同一）。

### 書き方（フェンスの info 文字列。`title="..."` と同じ流儀）

````text nocopy
```ts cite="src/lib/parser.ts:120-135"
（手で写した本文。実物のその範囲と行単位で完全一致していなければ --verify が失敗する）
```

```ts include="src/lib/parser.ts:120-135"
```

```ts cite="src/lib/parser.ts:120-135" rev="1a2b3c4d5e6f"
（引用した時点の commit の版と照合する）
```
````

| 属性 | 意味 |
|---|---|
| `cite="パス:開始-終了"` | **照合型**。本文は手で写す（説明のために行を並べ替えない）。実物のその範囲と食い違えば `--verify` が失敗する |
| `include="パス:開始-終了"` | **展開型**（写さずに引く）。本文は**書かない**。範囲を書くだけで、HTML にその範囲の実物の行が入る。写さないので写し間違いが起きない。引用は基本これを使う。**引けるのはソースコード・スクリプト・マークアップの拡張子のファイルだけ**（設定・データの形式は断られる。「`include=` で引けるファイルの種類」の節）。設定ファイルの行は `cite=` で書く |
| `rev="commit"` | 実物を git のその commit の版で見る（時点の固定）。省略時は今の作業ツリー。7〜40 桁の 16 進だけ（`HEAD`・ブランチ名は動くので不可。短い桁は、曖昧だったり、同じ名前のブランチ・タグがあったりすると照合できない扱いになるので、40 桁を勧める） |

- 範囲は**必須**（1 始まり・両端を含む）。`パス:行`で 1 行。全文の展開はできない。パスと範囲は末尾から分けるので、`C:/x/y.ts:12-20` のドライブ文字の `:` は割れない
- `cite=` と `include=` は同時に書けない。同じ属性を 2 回書く・値を `"..."` で囲まない・`rev=` だけを書く・`include=` なのに本文がある（空行・空白だけの行も不可。本文は 1 行も書かない）・`cite=` なのに本文が空・パスに制御文字を含む・mermaid / svg のフェンスに書く、はすべて「指定が不正」で失敗する（黙って読み替えない）
- **パスの解き方は 1 通りだけ**（候補を順に試さない。別のファイルに偶然合う誤合格を作らない）: `~/` はホームフォルダ。絶対パスはそのまま。**相対パスは、報告書 MD の最寄りの `.git`（ディレクトリでも、worktree のファイルでも）を持つ祖先フォルダ（リポジトリのルート）が起点**で、`.git` が無ければ報告書のあるフォルダが起点。別のリポジトリの実物は絶対パスで書く。絶対パスと `~/` は、別の PC では同じファイルを指さないことがある（その PC で `--verify` し直せば分かる）
- `rev=` を付けたとき、リポジトリは**照合先のファイルの実体のパス**から決める（シンボリックリンクで別のリポジトリへ逸れない）。その commit の時点に無いファイルは「ファイル無し」。今の作業ツリーから消えたファイルの過去の版も引ける

### 照合の厳密さ（行単位の完全一致）

CR（改行コードの違い）だけ無視する。**行末の空白もインデントも厳密**に比べる（エディタが行末の空白を削る環境では `cite=` が落ちる。そのときは `include=` を使う）。箇条書きなどの中でインデントして書いたフェンスは、開きの行頭の空白の数だけ各行の頭から取り除いて比べる（Markdown のコンテナの字下げであって、実物の字下げではない。実物の字下げは厳密なまま）。BOM はファイル先頭の 1 個だけ除く。実物は UTF-8 で読み、読めなければ照合できない扱い。ファイル末尾の改行が作る空の 1 行は行数に数えない。

### `include=` で引けるファイルの種類（許可リスト・道具の約束）

報告書の HTML は共有の場所に置かれ、git に commit され、人やほかの AI に読まれる。`include=` は道具がファイルの中身を自動で HTML に入れるので、書き手が中身を見ずに秘密（パスワード・トークン・鍵）を報告書へ入れてしまう道になる。そこで、秘密の形を当てるのでなく、**引いてよいファイルの種類を決めて、それ以外を断る**。

**道具が約束すること（これだけが保証）**

- **G1**: `include=` は、**最後の拡張子が下の一覧にあるファイルだけ**を引ける。判定は大文字小文字を区別せず、①書かれたパス ②実体のパス（シンボリックリンク・ジャンクションの先、Windows の短い名前を直したもの）③ `rev=` のときはリポジトリ内の正規のパス、のすべてに当てる。一覧にない拡張子（拡張子の無いファイル、`.env` や `.json` のようにドットで始まるだけの名前を含む）は、**ファイルを開く・行を数える・git の中身を読むより前に**断る
- **G2**: 一覧にない種類のファイルの `cite=` は、照合はするが、**食い違いの診断に実物の行を出さない**。出すのは、書き手が書いた行・行番号・行数・「引用が実物の別の範囲と一致する」ことだけ（行末の空白だけが違う、のような実物への近さの手がかりも出さない）

**約束しないこと**

- 名前ではなく**中身の形式**（許可された拡張子のファイルに設定が入っている場合。例: `credentials.js`、`deployment.yaml.ts`、JSON を `data.ts` として保存したもの）
- ハードリンク（同じ中身に別の名前が付いていても、拡張子では見分けられない）
- 許可された拡張子のファイルの中に、ソースコードとして書かれた秘密。次の小節の「第 2 の網」が拾える範囲で拾うが、約束の外

**許可する拡張子（最後の拡張子・小文字）と決め方**

| 区分 | 拡張子 |
|---|---|
| ソースコード | `ts` `tsx` `mts` `cts` `js` `jsx` `mjs` `cjs` `py` `pyi` `go` `rs` `java` `kt` `kts` `swift` `c` `h` `cc` `cpp` `cxx` `hpp` `hh` `cs` `rb` `php` `lua` `pl` `pm` `r` `scala` `dart` `ex` `exs` `erl` `hs` `ml` `clj` `groovy` `vue` `svelte` `astro` |
| スクリプト | `sh` `bash` `zsh` `ps1` `psm1` `bat` `cmd` |
| マークアップ・文書・スタイル | `md` `mdx` `html` `htm` `css` `scss` `sass` `less` |
| インタフェース・スキーマ言語 | `proto` `graphql` `gql` |

- **決め方**: プログラムやマークアップの本文を書くための形式を許可し、**値を保存するための形式と、知らない拡張子は断る（既定は拒否）**。断る例: `json` `jsonc` `json5` `yaml` `yml` `toml` `ini` `cfg` `conf` `config` `properties` `env` `xml` `plist` `sql` `txt` `log` `csv` `tsv` `lock` `ipynb` `tf` `tfvars` `hcl` `gradle` `svg` `pem` `key`、拡張子の無いファイル（`Makefile`・`Dockerfile`・`.bashrc`）。`.txt` は出力やデータが混ざるので断る
- **根拠**: このリポジトリの既存の報告書（`report_id` を持つ文書約 780 本）のコードブロック 1538 個のうち、言語名が付いたものはソースコード・シェル・Markdown が大半で、`json` と `yaml` は 61 個（約 4%）。許可リストは、ふつうのコードの引用を妨げない
- 断られたときの出力は `[引けない種類のファイル]` で、理由（拡張子）と `cite=` で書く案内が出る。設定ファイルを見せたいときは、**見せたい行を `cite="パス:開始-終了"` の本文として自分で書く**。実物との照合は行われ、食い違いの診断に実物の行は出ない（G2）。秘密を含む行は書かない
- 例外を開けるスイッチ（環境変数・フラグ）は無い

### 第 2 の網: 名前・場所・値の形で止める（約束の外・拾える範囲で拾う）

許可リストの内側のファイル（ソースコード）にも、パスワードを直接書いたものがありうる。そこで `include=` と `cite=` の両方で、次の 2 段でも止める。これは**名前・場所・値の形によるヒューリスティック**で、約束（G1・G2）ではない。止めたときは `秘密の疑い` として失敗し（終了コード 1）、`include=` の文書は HTML を生成しない。

- **パスで止める（中身を読まない）**: 書かれたパスと、実体のパス（シンボリックリンクの先・ジャンクション・Windows の短い名前や大文字小文字を実際の名前に直したもの）の両方を見る。パスの書き方も絞る: ドライブ文字以外のコロン（Windows の代替データストリーム `ファイル:名前`）・`?` `*` `<` `>` `|` `"`・名前の末尾のドットや空白は、読む前に「指定が不正」で失敗させる（Windows が黙って落として同じファイルを指すため）。次の形は、中身を読まずに止める
  - フォルダ名: `.ssh`・`.gnupg`・`.aws`・`.azure`・`.kube`・`.docker` の下のファイル
  - `.ccpit` の直下のファイル（設定・状態）。`.claude` の直下の `settings.json`・`settings.local.json`・`.credentials.json`・`credentials.json`。`.claude.json`
  - ファイル名: `.env`・`.env.*`・`.npmrc`・`.pypirc`・`.netrc`・`.git-credentials`・`.htpasswd`・`.dockercfg`・`credentials*`・`secret(s)*`・`id_rsa` など秘密鍵の名前・拡張子 `.pem`・`.key`・`.p12`・`.pfx`・`.jks`・`.keystore`・`.kdbx`・`.tfstate`・`.tfvars`・`.ppk`・`.secret`
  - 例外: 書き方の見本のファイル（`.env.example`・`.sample`・`.template`・`.dist`）と公開鍵（`id_rsa.pub`）、`.claude` の下の `skills` などの普通のファイル、`.ccpit/proposals` の下のファイルは対象外
- **中身で止める（その行を出さない）**: 引く範囲の行に、秘密鍵のブロック（OpenPGP の `PRIVATE KEY BLOCK` を含む）・HTTP の `Authorization: Basic …`・AWS のアクセスキー ID・GitHub / Slack / Google / `sk-` のトークン・ベンダー固有の接頭辞のトークン（Docker `dckr_pat_`・npm `npm_`・GitLab `glpat-`・PyPI `pypi-`・Hugging Face `hf_`・Stripe `sk_live_` など・Anthropic `sk-ant-`・SendGrid・Twilio ほか。キー名が何でも形で止める）・Base64 化された PEM（`LS0tLS1CRUdJTi…`）・JWT・Bearer トークン・URL に埋め込まれた資格情報（`scheme://user:パスワード@host`）・XML の `<password>値</password>`・名前と値が別の属性（`<add key="ApiKey" value="…" />`・`{"name": "client_secret", "value": "…"}`）・接続文字列（`Password=`・`AccountKey=`・`SharedAccessKey=` など。値が鍵らしい形のときだけ）・引用符つきの認証情報の代入（Bash の `$'…'` も）（`password = "…"`・`"token": "…"` など、値が 8 文字以上）・環境変数の形の代入（`API_KEY=…`）・YAML や TOML の引用符なしの値（`api_key: …` で、数字を含む 16 文字以上、または数字を含まなくても大文字と小文字が混ざった英字だけの 20 文字以上）・キーだけの行の次の行に書かれた値（値の行だけを引く場合も、1 行前のキーを見て止める）があれば止める。値の後ろの行内コメント（`# …`）は無視して判定する。**資格情報のキー（`password`・`token`・`api_key` など）の行が、値を次の行以降に続ける形で終わる場合、続く行は値の形に関わらずブロックの内側として止める**（複数行に分けた値を、1 行ずつの形では判定できないため）。資格情報のキー名には、`password`・`secret`・`token`・`api_key`・`access_key`・`private_key`・`tls.key`・`client.key`・`signing.key`・`encryption.key`・`auth.key`・`credential` を含み、`.` `_` `-` の区切りの違いは問わない（`api.key=…` も同じ）。続ける形は 5 つ: ①値が空、または YAML の `|` `>`（桁数・`+` `-` の記号つきも）・アンカー（`&名前`）・タグだけ → 下にインデントされた行（そのキーの下の入れ子の設定も止まる）、②行末が `\`（`.properties`・シェル）→ `\` で終わる限り次の行、③ TOML の `"""` や `'''` を同じ行で閉じていない → 閉じる行まで、④ヒアドキュメント `<<WORD` → `WORD` だけの行まで（区切り語に記号が入っていてもよい）、⑤閉じていない引用符（YAML の複数行の引用符つき文字列・シェルの複数行の代入・`$'…'`・JavaScript のテンプレートリテラル）→ 閉じる引用符のある行まで（キーの行も含めて止める）。④⑤と③の閉じる印がファイル内に見つからないときは、コメントや説明文に書かれた例をファイルの終わりまで続くブロックと取り違えないよう、20 行で打ち切る。JSON でキーと値が別の行に書かれた場合も、値の行（引用符・末尾のカンマを外して判定）を止める。**秘密鍵のブロック（`BEGIN … PRIVATE KEY` から `END … PRIVATE KEY` まで。`END` が無ければファイルの終わりまで）の内側の行は、`BEGIN` の行を含まない範囲でも止める**（ブロックの境界は、行全体がそのマーカーだけの行）。失敗の出力には、パス・何の形か・範囲の中の行番号だけを出し、**行の中身は出力にも HTML にも入れない**
- 例外を開けるスイッチ（環境変数・フラグ）は無い。普通のコードの誤検知は、引く範囲を絞って秘密の形の行を含まない範囲にする。それでも引きたいファイルは、その部分を手で説明に書く
- 検査の時点で存在しないファイルは、読む試みもしない（検査の後に同名のリンクが作られても、検査していない別のファイルを読まないため）。存在するファイルは、検査した実体のパスを開き、**開いたファイルそのもの**から読み、読んだ後に「同じ実体のパスが、同じファイル（デバイスと inode が同じ）を指している」ことを確かめる。検査と読み出しの間にリンク先が差し替えられたとき（読む瞬間だけ別のファイルを指し、読んだ後に元へ戻す操作も含む）は `UNVERIFIABLE`（照合している間に実体が変わった）として失敗し、読んだ中身は使わない。`rev=` は、検査したリポジトリ内のパスをそのまま git の読み出しに渡す。同じプロセスの中で実物の読みを使い回す仕組み（スナップショット）も、検査済みのパスそのものを索引にし、解決し直さない
- **この第 2 の網は、名前・場所・値の形で見るヒューリスティックで、約束の外**（約束は上の G1・G2）。書き方の変種は尽きないので、形に当てはまらない秘密は止められない。確認済みで止められない例: 短い平文のパスワード、小文字だけの引用符なしの値、Kubernetes の Secret の `.dockerconfigjson` のような、キー名も値の形も一般的でない Base64 の値、インデントの無いフロー形式の続き行。設定ファイル（YAML・TOML・JSON・INI・`.properties`・XML・`.config`・Kubernetes のマニフェストなど）は `include=` では引けない（許可リスト）。**許可された拡張子のファイルでも、秘密を含むと分かっているものは引かない**
- 限界（続き）: 検出は名前・場所・値の形による。形に当てはまらない秘密（短い平文のパスワード、小文字だけの引用符なしの値など）は止められない。識別子らしい値（`token: nextTokenFromQueue` のような 20 文字未満の英字）は止めないが、20 文字以上の大文字小文字混じりの識別子は誤って止まることがある（範囲を絞る）。**秘密を含むと分かっているファイルは、そもそも引かない**

### `--verify` の出力

宣言が 1 つも無い文書は何も出さない。宣言がある文書は、全部合えば `[VERIFY CITE OK] N 件 実物と一致` と各引用の実物のパス（rev 付きは完全な commit も）を出す。1 つでも合わなければ `[VERIFY CITE FAIL]` と引用ごとの理由を出し、**終了コード 1**:

| 種別 | 意味 |
|---|---|
| `中身違い` | 範囲は実在するが行が違う。最初の食い違いの行（引用 / 実物）を併記。行末の空白だけの違いはそう書く |
| `範囲ずれ` | 引用の全行が、実物の**別の範囲**に完全一致する。実際の範囲を併記する（行を足されただけなら書き直す範囲がそのまま分かる） |
| `ファイル無し` | 実物のファイルが無い |
| `範囲が実物を超える` | 指定した行が実物の行数を超える。実物の行数を併記 |
| `指定が不正` | 範囲が読めない・属性の誤用・rev が commit の形でない、など |
| `引けない種類のファイル` | `include=` で、許可リストにない拡張子のファイルを引いた（ファイルは開かない）。`cite=` で書き直す |
| `秘密の疑い` | パスが秘密を含みうるファイルの形、または引く範囲の行に秘密の形がある（上の節）。行の中身は出さない |
| `UNVERIFIABLE 照合できない` | 実物を読めない・UTF-8 でない・rev の commit が無い（短縮が曖昧）・git を実行できない・リポジトリの外のファイルに rev を付けた・相対パスの起点が決まらない。**合格にはならない**（「実物が無いだけ」「中身が違う」と別のタグで読み分ける） |

照合を飛ばす手段（フラグ・環境変数）は無い。`--verify-html` / `--verify-md`（片方向のデバッグ用）は従来どおり引用の照合を行わない。

### 展開型 `include=` の動き

- HTML のコードブロックの中身は実物の行になる。バーのラベルは、`title="..."` が無ければ `パス:範囲`。コピーボタンが写すのも実物の行
- 展開した行は `--verify` の HTML⊆MD で「宣言された実物由来の行」としてコーパスに足される（MD⊆HTML は展開後の行で被覆を見る）。静的なテキストノードは増えない
- 展開に失敗した `include=`（ファイル無し・UNVERIFIABLE など）の文書は、HTML を生成しない（`[RENDER FAIL]`・終了コード 1・出力先は書き換えない）。本文の欠けた HTML を黙って出さない
- 同じプロセスの中では、実物を 1 度だけ読み、その同じ読みを描画・照合・`--check` のハッシュに使う。読んでいる間に実物が書き換わっても食い違わない

### 報告書を書いた後で実物が変わったとき

- **`rev=` なし（既定）= 今の作業ツリーの実物と照合する**。コードが進んで食い違えば、過去の報告書の `--verify` も失敗する（引用は「いま実物がこうだ」という主張だから）。行が足されただけなら `範囲ずれ` が新しい範囲を出すので、書き直しは機械的
- **`rev="<commit>"` を付けた引用は、その commit の版と照合する**。その後コードが進んでも失敗しない＝報告書が後からの変更で壊れない。時点を固定したい引用（検収済みの報告書・差し戻しの記録）は `rev=` を付ける。未コミットの実物を引いているときは付けられないので、commit してから `rev=` を足す
- `include=`（`rev=` なし）の HTML は「引用した時点の作業ツリーの写し」。HTML の埋め込みハッシュ（`data-src-sha256`）は、そのとき**MD＋展開した行**から作るので、実物が変わると `--check` が STALE を出す（作り直す合図）。`rev=` 付きは時点が固定なので変わらない。`include=` を使わない文書のハッシュは従来と同じ
- 決定論の範囲: 同じ MD から同じ HTML になるのは、`include=` を使う文書では「同じ MD **と同じ実物**」のとき（`rev=` 付きなら同じ commit が引けるとき）

### 限界

- **宣言しない引用は検査されない**。コードを引用するときは、`include=` か `cite=` で書く運用にする（書かなければ従来どおり何も照合されない）
- 照合するのは「その範囲の行が一致しているか」まで。引用が説明の根拠として正しいかは読み手が見る
- `cite=` は引用の途中を省略できない（省略したいときは、範囲を分けて 2 つの引用にするか、`include=` を使う）
